## 一、实验目的

本实验在 Lab 1 已能够启动 uCore 内核的基础上，学习物理内存的探测、初始化和分配，并结合 RISC-V 的分页机制理解物理内存与虚拟内存的关系。主要目标如下：

1. **掌握物理内存探测和初始化方法。** 通过设备树获取物理内存范围，建立 `Page` 描述符数组，正确区分内核占用页面和可分配页面。

3. **理解伙伴系统及小块内存分配。** 通过 Buddy System 学习按 2 的幂次组织、拆分与合并空闲块；通过选做的 SLUB Challenge 了解在页级分配之上管理不同大小内存对象的方法。
4. **理解物理内存管理与页表机制的联系。** 结合 RISC-V Sv39 分页，区分虚拟地址、物理地址、物理页号和页面描述符，理解页表映射与物理页分配分别解决的问题。

## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

本实验围绕**如何让内核识别、组织和分配物理内存**展开。主要解决了操作系统如何确定哪些物理内存可以使用，以及如何高效地分配和回收这些内存的问题。

实验一已经使内核能够在 QEMU 上启动，但启动成功不代表内核已经知道哪些物理页可以安全分配。设备树只能提供 RAM 的位置和大小，其中一部分物理内存已经被 OpenSBI、内核镜像和管理数据占用。因此，首先要探测物理内存并建立 `Page` 描述符，保留已使用页面，再将可用页面交给分配器。

物理内存管理器通过 `struct pmm_manager` 的函数指针接口提供初始化、分配、释放和检查等操作。首先理解框架已有的 First-Fit，再实现 Best-Fit，可以在保持基本接口相同的前提下比较两种选择空闲块的方式。Buddy System 则从另一种角度组织空闲内存：按 2 的幂次管理块，分配时拆分、释放时合并。任务三的 SLUB Challenge 进一步面向任意大小的内存对象，在页级分配之上提供更细粒度的分配能力。

### 2.2 功能的逐步实现

1. 首先实现物理内存探测与初始化功能 → 因为操作系统必须先知道物理内存的范围，以及哪些页面已经被占用、哪些页面可以使用，才能为后续的内存分配提供基础。
2. 接着理解 First-Fit 算法并实现 Best-Fit 分配器 → 在完成物理页初始化后，需要能够对空闲物理页进行分配和回收。通过分析已有的 First-Fit 实现，再完成 Best-Fit，可以掌握连续物理页分配的基本过程，并理解不同空闲块选择策略的区别。
3. 然后实现 Buddy System 伙伴分配算法 → 在掌握基本连续物理页分配方法后，进一步学习按照 2 的幂次组织空闲块，通过拆分和伙伴合并实现物理内存管理，理解另一种内存分配策略。
4. 最后补充 SLUB 内存分配扩展功能 → 前面的算法主要以物理页或连续页块为单位进行分配，而实际系统还需要分配小于一页、大小不同的内存对象。因此在页级分配的基础上进一步实现 SLUB，并通过相应测试验证内存对象的分配与释放，形成从物理页管理到小块内存分配的完整过程。

遍历整个空闲链表，在所有大小不小于 `n` 的空闲块中选择大小最小的块。

如果存在多个同样大小的候选块，可以选择遍历时最先遇到的块。

特别地，若在遍历过程中发现某个候选块的大小恰好等于 `n`，则可直接终止后续搜索并选中该块，因为它已经是满足条件的最小可用块，不可能再有更小的候选块；只有在未发现大小等于 `n` 的块时，才需要继续比较更大尺寸的候选块以确保选择最小满足块。

**Case 3：选中的空闲块恰好等于 n**

直接分配整个空闲块，将它从空闲链表移除，并清除相应的空闲块头页标志。

**Case 4：选中的空闲块大于 n**

分配该块的前 `n` 页，将剩余连续页面组成新的空闲块，设置新的头页、空闲块大小及标志，并保持链表地址有序。

**Requirements：**
- 必须实现真正的 Best-Fit，而不是找到第一个合适空闲块就停止。
- 分配成功后 `nr_free` 减少 `n`。
- 不得破坏其他空闲块的链表关系。

## 4. best_fit_free_pages()

**Pre-Condition：**
- `base` 指向待回收的连续页面。
- `n > 0`。
- 待回收页面应满足合法回收条件。

**Post-Condition：**
- 清空待回收页面的管理状态及引用计数。
- 将回收区域重新登记为空闲块。
- 空闲页总数增加 `n`。
- 空闲链表保持地址升序。
- 与前后物理地址连续的空闲块完成合并。

**Case 1：不存在相邻空闲块**

将回收区域作为独立空闲块插入链表。

**Case 2：与前一个空闲块连续**

将回收区域合并到前一个空闲块，更新其 `property`，移除多余链表节点及头页标志。

**Case 3：与后一个空闲块连续**

**Case 4：与前后两个空闲块均连续**

**功能说明：**

本模块作为 uCore 的独立物理内存管理器，实现 Buddy System 分配算法。新增 `buddy_system_pmm.c`，定义 `buddy_system_pmm_manager`，通过现有 `pmm_manager` 接口向内核提供物理页分配、释放和空闲页数查询功能，保留原有 fit 算法。

主要处理以下场景：

- **可用区间初始化：**支持起始物理页号不满足最大块对齐、页数不是 `2` 的幂的区间，将其完整划分为若干对齐的 `2^u` 页空闲块。
- **分配与拆分：**按地址顺序寻找第一个满足请求的空闲块，逐级二分至最小满足大小；保存实际分配阶数，并维护剩余空闲块和页数统计。零页、超大或可能溢出的请求返回 `NULL`。
- **释放与合并：**检查释放地址、页数和分配状态，根据保存的阶数归还实际占用的整个块；仅合并同阶、相邻且满足伙伴对齐条件的空闲块，禁止跨越保留页或不可用区域。
- **状态维护与自检：**维护块头标记、阶数、链表顺序及空闲页数；验证取整、连续拆分、多级合并、分配失败、非伙伴不合并和释放后状态恢复。

本模块复用 `Page`、`list.h`、页状态宏及地址转换工具，在 `Page` 中增加阶数成员 `u`，以物理页号判断对齐和伙伴关系。空闲链表按块起始地址递增排列，每个空闲块仅由块头节点表示。

通过修改现有 `init_pmm_manager()`，将 `pmm_manager` 指向 `&buddy_system_pmm_manager`，使内核通过原有包装接口调用本模块，并通过 `.check = default_check` 执行自检。除必要的字段、声明、构建配置和管理器选择外，不修改其他内核模块。

### 练习：任务一：理解first-fit 连续物理内存分配算法（思考题）

**负责人：** 2513447-黄天怡
**1.理解First-Fit算法的实现过程**
First-Fit算法的基本思想：
    从空闲链表头部开始查找，找到第一个能够满足分配需求的空闲块。

相关变量的含义：
    双向循环链表 free_list 管理空闲块，按照物理地址升序排列。每个空闲块通过头页的 page_link 加入链表，property 记录该块的页数，nr_free 记录总空闲页数。

主要函数的作用：
- default_init()： 初始化空闲链表，将空闲页总数 nr_free 设为 0。

- default_init_memmap()： 将指定的连续物理页初始化为空闲块，清空各页状态，设置头页的 property 和 PG_property 标志，并按地址顺序加入空闲链表。

- default_alloc_pages()： 遍历空闲链表，找到第一个大小不小于请求页数的空闲块。如果空闲块更大，就将剩余页面重新组成空闲块；如果恰好相等，则直接分配整个块。最后更新空闲页数量并返回分配结果。

- default_free_pages()： 将回收的页面重新加入空闲链表，并检查其前后是否存在物理地址连续的空闲块。如果相邻，就将它们合并成更大的空闲块，以减少内存碎片。

用自己的话说明一些过程：
- 如何初始化空闲页：
  - 清空页的元数据（flags property 引用计数），初始化标志位，然后加入空闲链表。
- 如何分配连续物理页：
  - 遍历寻找第一个大于等于n的块，返回头页的指针，如果更大，就把剩下的页整理成一个新的空闲块。如果没找到，返回NULL。
- 如何回收页面并合并相邻空闲块：
  - 将回收的页面加入空闲链表，检查地址的连续性，如果和前后存在连续，则向前或向后合并。

**2.原有的first fit算法是否有进一步的改进空间？**
是，比如优化分配策略： First-Fit 只选择第一个满足要求的空闲块，不一定最合适。可以使用 Best-Fit 算法，选择满足要求的最小空闲块，但也可能产生更多难以利用的小碎片。

### Challenge：[硬件的可用物理内存范围的获取方法（思考题）]

**负责人：** [2510943-张艺涵]

**如果 OS 无法提前知道当前硬件的可用物理内存范围，请问你有何办法让 OS 获取可用物理内存范围？**
- 设备树解析：Bootloader向内核传递设备树基址，内核解析其中的memory节点，读取各段物理内存的起始地址与长度，初步获取内存布局。
- 固件内存映射接口：x86平台通过BIOS中断或UEFI运行时服务获取系统内存映射表，区分可用RAM、内存映射IO区与硬件保留区，筛选可用区间。
- 启动参数传递：Bootloader将内存起始地址、总大小封装为约定格式的启动参数，通过指定寄存器或内存地址传递给内核，供内核直接读取初始化。
- 主动内存探测扫描：无固件与设备树支持的场景下，内核通过写入-回读一致性校验逐地址试探，根据访问结果判定可用内存范围，该方式效率低、存在硬件访问风险，仅作为兜底方案。
- 内核区间过滤校验：内核对原始内存区间做二次过滤，剔除内核镜像占用区、内存映射IO区与固件预留区，仅将剩余可用RAM纳入页分配器管理。

- 实际执行项目支持的构建和检查。完成后简要列出修改文件、测试覆盖及结果；无法运行时说明具体阻碍，不得将静态检查描述为运行通过。

## 六、实验总结与收获

### 对操作系统的理解

| 本实验的重要知识点 | 对应的 OS 原理知识点 | 二者的含义、联系与差异 |
|---|---|---|
| Buddy System 的拆分与合并 | 连续内存分配与碎片管理 | 实验将物理页组织为 `2^u` 页的块，通过拆分满足请求，通过伙伴合并恢复大块。它体现了利用对齐关系简化管理的原理，但申请大小需要向上取整，例如申请 3 页实际占用 4 页，仍存在内部碎片。 |
| 通过 `pmm_manager` 接入分配算法 | 操作系统的模块化与接口抽象 | 不同分配算法通过统一接口提供服务，上层调用方式保持一致。但接口一致不代表内部规则相同：fit 可以按连续页数管理，Buddy 则需要保存实际分配阶数，保证释放和页数统计正确。 |
|物理内存探测与初始化|物理内存管理|本实验通过设备树获取内存范围，利用 Page 描述符管理物理页。两者都涉及物理内存资源的组织与管理，区别在于本实验主要完成空闲页的初始化，而完整的物理内存管理还包括页面分配与回收|
|虚实地址转换与页面对齐|分页存储管理|本实验利用已有映射关系完成虚实地址转换，并通过页面对齐保证分配完整物理页。两者都涉及分页机制，但本任务没有涉及页表的建立、缺页处理和页面置换|

OS 原理中重要、但本实验没有涉及的知识点：

- **页面置换：**物理内存不足时，根据访问情况选择页面换出，并通过缺页异常重新调入。本实验主要管理物理页的分配与回收，没有涉及页面换入换出及置换策略。

### AI 协作开发的经验

- **AI 协作中出现的具体问题或有帮助的做法：**最初的提示词没有明确 Buddy 对非 `2` 的幂次请求的释放规则，也没有充分说明伙伴对齐条件。
- **自己如何分析、核查或修正：**结合“申请 3 页实际占用 4 页”的例子，补充保存阶数、按实际块大小回收的要求；分析原有 fit 测试后，明确其部分释放方式不能直接用于 Buddy，并增加非伙伴相邻块不能合并的测试场景。
- **最终结果及得到的经验：**完善了实现提示词和测试要求。认识到 AI 生成代码前需要明确接口语义与边界条件，生成后还应通过源码核查和实际测试验证，不能仅凭代码完整就认定实现正确。
- 明确提示词可以提高代码生成的准确性。 通过四段式 Prompt 提供工程依赖、接口和边界条件，使 AI 能够按照实际需求完成代码，减少反复修改。
- AI 生成的代码需要实际验证。 本次通过编译和 QEMU 测试检查功能，并在独立副本中解决其他模块造成的编译阻碍，认识到需要结合测试结果分析问题，而不能仅依赖 AI 的代码生成结果。
