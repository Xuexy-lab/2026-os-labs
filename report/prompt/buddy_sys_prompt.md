**Buddy System 原理概述**
- 将空闲内存组织为大小为 `2^u` 页的块，`u` 表示块的阶数。
- 分配时，将请求页数 `n` 向上取整到最小的 `2^u`，必要时通过递归二分获得所需块。
- 释放时，仅合并大小相同、地址相邻且满足伙伴对齐条件的两个空闲块，持续合并直到无法继续。

1. **初始化**
   - 初始化空闲链表和空闲页计数。
   - 不得假设传入可用区间的页数为 `2` 的幂，也不得假设起始地址天然满足最大块对齐。
   - 将可用区间拆成若干满足大小及对齐要求的 `2^u` 页块，全部纳入管理，不丢弃尾部页。
   - 使用物理页号作为伙伴关系和对齐判断的统一坐标；不得使用 `Page *` 的字节地址计算伙伴。
   - 不得跨越保留页、不可用区间或未纳入管理的区域进行合并。

2. **分配流程**
   - 接口参数若为 `size_t`，不存在可表示的负数；应拒绝 `n == 0`、超出可管理块大小以及可能导致计算溢出的请求，并返回 `NULL`。
   - 从空闲链表头开始，找到第一个大小 `>= n` 的块，取得其阶数 `i`。
   - 若 `i > 0` 且 `n <= 2^(i-1)`，将该块二分，继续对其中一半进行拆分。
   - 重复上述过程，直到 `i == 0` 或满足 `2^(i-1) < n <= 2^i`，完成分配。
   - 将拆分产生的剩余空闲块按地址有序插回链表，维护其阶数、页状态和链表节点。
   - 保存返回块的实际分配阶数；空闲页数应减少实际占用的 `2^i` 页，而非原始请求的 `n` 页。
   - 无满足条件的块时返回 `NULL`，不得破坏已有状态。

3. **释放与合并**
   - 检查释放地址、页数及分配状态，防止释放保留页、重复释放或释放非块头地址；按现有内核风格使用断言或错误处理。
   - 根据分配时保存的阶数恢复实际块大小，兼容上层使用原始请求页数 `n` 释放的方式。
   - 将释放块标记为空闲，并按地址寻找插入位置。
   - 仅当两个块同时满足以下条件时合并：
     - 均为空闲块；
     - 阶数相同，大小均为 `2^i` 页；
     - 地址相邻；
     - 低地址块的起始物理页号是 `2^(i+1)` 的倍数；
     - 合并后的整个范围均属于可管理内存。
   - 合并后以低地址块为新块头，阶数增加 `1`，继续尝试向上合并。
   - 清理被合并块头的旧标记和链表节点，避免重复挂链或残留块头。
   - 空闲页数仅在归还实际分配块时增加一次，合并过程不得重复计数。
