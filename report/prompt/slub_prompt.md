[Guarantee]
1. 管理器接入
完整实现 slub_pmm_manager 的所有回调：
- init：初始化 Buddy，再初始化 SLUB 的静态 cache 和空链表。
- init_memmap：委托 Buddy 注册可用物理页。
- alloc_pages、free_pages：直接委托 Buddy。
- nr_free_pages：返回 Buddy 的空闲页数。
- check：依次执行 Buddy 和 SLUB 自检。
适配回调直接调用 buddy_system_pmm_manager 的对应函数，避免通过上层包装函数调用自身，产生无限递归。模块内部辅助函数使用 static，避免符号冲突。
2. 数据结构与初始化
   - 设置固定大小类别：16、32、64、128、256、512、1024、2048 字节。
   - 每个小对象 slab 占一页，同一 slab 只容纳同一大小类别的槽位。
   - 每个 cache 维护仍有空闲槽位的 slab 链表。
   - 每个 slab 记录所属 cache、底层页、总槽位数、已分配数及 freelist。
   - 空闲槽位内部存放 next 指针；分配后整个槽位交给调用者使用。
   - 管理头与对象区均满足至少 16 字节对齐。
   - 计算容量时扣除管理信息、必要的检查信息及对齐开销，不得覆盖管理区或越过页边界。
   - slub_init() 只初始化静态管理结构，不得申请页面，也不得通过 kmalloc() 分配自身的启动管理结构。
3. 小对象分配
kmalloc(size) 应：
- 对 size == 0 返回 NULL。
- 选择能够容纳请求的最小大小类别。
- 从对应 cache 的可用 slab 中取得一个空闲槽位。
- 无可用 slab 时，申请一页，初始化管理信息和空闲链表。
- 更新 freelist 和已分配计数；slab 满时从可用链表摘除。
- 分配失败时返回 NULL，不得泄漏页面或破坏已有状态。
4. 小对象释放
kfree(ptr) 应：
- 对 NULL 不做操作。
- 根据原始返回指针找到所属 slab。
- 检查槽位边界及分配状态，使用必要的位图或等效方式检测页内重复释放等错误。
- 将槽位插回空闲链表，减少已分配计数。
- 原先满的 slab 出现空位后重新入链，避免重复挂链。
- 最后一个对象释放后，先摘链并保存底层页信息，再将整页归还 Buddy。
- 页面归还后不得继续访问其中的管理信息。
不合并相邻对象槽位；页面归还后的伙伴合并由 Buddy 完成。
5. 大对象分配与释放
   - 大于 2048 字节的请求直接申请连续页。
   - 按“请求大小 + 管理开销”计算所需页数，兼容 Buddy 向上取整到 2 的幂页数的行为。
   - 记录分配类型、页块首描述符和实际占用页数。
   - 返回满足对齐要求、至少可使用 size 字节的内存。
   - kfree() 应可靠地区分小对象和大对象，并准确归还整个大对象页块。
   - 若通过指针向下按页取整查找管理头，应保证大对象的原始返回指针位于页块第一页。
   - 所有加法、对齐、页数计算和幂次取整均需检查溢出。
6. 自检
slub_check() 至少覆盖：
- 零大小、各大小类别边界及超过最大类别的请求。
- 返回地址对齐，可写满请求范围，多个对象内容不互相覆盖。
- 同一 slab 内的多次分配、释放及槽位复用。
- slab 满、重新出现空位、跨 slab 分配。
- 不同大小类别的独立管理。
- 大对象分配及完整回收。
- 内存不足或超大请求失败时，已有状态不变。
- 全部释放后，Buddy 空闲页数恢复到测试前。
- 每个存活 slab 满足：
已分配槽位数 + 空闲槽位数 = 总槽位数
自检不得遗留对象、页面或链表状态。
