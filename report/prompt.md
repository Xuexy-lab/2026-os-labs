设备树提供有效的物理内存信息时，应正确确定物理内存范围，并建立 Page 描述符数组。描述符数组位于内核镜像结束位置之后，且按页对齐。

**Case 4：描述符数组空间不足**

描述符数组需要覆盖全部可管理物理页，其本身占用的内存也必须排除在空闲区之外。

**Case 5：完整空闲页的处理**

空闲区应从描述符数组之后开始，并正确处理页面对齐。只允许将完整的、未被占用的物理页注册给分配器。

如果剩余空间不足一个完整页面，不得调用 `init_memmap()`；如果存在完整空闲页，则应保证传入的起始 Page 描述符和页面数量正确。

**Buddy System 原理概述**

[SPECIFICATION]

1. **初始化**
   - 初始化空闲链表和空闲页计数。
   - 不得假设传入可用区间的页数为 `2` 的幂，也不得假设起始地址天然满足最大块对齐。

2. **分配流程**
   - 接口参数若为 `size_t`，不存在可表示的负数；应拒绝 `n == 0`、超出可管理块大小以及可能导致计算溢出的请求，并返回 `NULL`。

   - 若 `i > 0` 且 `n <= 2^(i-1)`，将该块二分，继续对其中一半进行拆分。

   - 将拆分产生的剩余空闲块按地址有序插回链表，维护其阶数、页状态和链表节点。
   - 保存返回块的实际分配阶数；空闲页数应减少实际占用的 `2^i` 页，而非原始请求的 `n` 页。
   - 无满足条件的块时返回 `NULL`，不得破坏已有状态。

3. **释放与合并**
   - 检查释放地址、页数及分配状态，防止释放保留页、重复释放或释放非块头地址；按现有内核风格使用断言或错误处理。

   - 将释放块标记为空闲，并按地址寻找插入位置。
   - 仅当两个块同时满足以下条件时合并：
     - 均为空闲块；
     - 阶数相同，大小均为 `2^i` 页；
     - 地址相邻；
     - 低地址块的起始物理页号是 `2^(i+1)` 的倍数；
     - 合并后的整个范围均属于可管理内存。
   - 合并后以低地址块为新块头，阶数增加 `1`，继续尝试向上合并。
   - 清理被合并块头的旧标记和链表节点，避免重复挂链或残留块头。
   - 空闲页数仅在归还实际分配块时增加一次，合并过程不得重复计数。

**Pre-Condition：**

- 空闲页总数增加 `n`。

## 3. best_fit_alloc_pages()

**Pre-Condition：**
- `n > 0`。
- 空闲链表及空闲页数量记录有效。

**Post-Condition：**
- 如果分配成功，返回连续 `n` 个物理页的起始 `Page` 指针，更新空闲链表及空闲页数量。
- 如果分配失败，返回 `NULL`，不改变空闲内存管理状态。

**Case 1：没有满足要求的空闲块**

遍历后不存在大小不小于 `n` 的连续空闲块，返回 `NULL`。即使总空闲页数足够，也不能将不连续的页面拼接成一个分配结果。

**Case 2：存在满足要求的空闲块**

遍历整个空闲链表，在所有大小不小于 `n` 的空闲块中选择大小最小的块。

如果存在多个同样大小的候选块，可以选择遍历时最先遇到的块。

**Case 3：选中的空闲块恰好等于 n**

直接分配整个空闲块，将它从空闲链表移除，并清除相应的空闲块头页标志。

**Case 4：选中的空闲块大于 n**

分配该块的前 `n` 页，将剩余连续页面组成新的空闲块，设置新的头页、空闲块大小及标志，并保持链表地址有序。

**Requirements：**
- 必须实现真正的 Best-Fit，而不是找到第一个合适空闲块就停止。
- 分配成功后 `nr_free` 减少 `n`。
- 不得破坏其他空闲块的链表关系。

## 4. best_fit_free_pages()

**Pre-Condition：**
- `base` 指向待回收的连续页面。
- `n > 0`。
- 待回收页面应满足合法回收条件。

**Post-Condition：**
- 清空待回收页面的管理状态及引用计数。
- 将回收区域重新登记为空闲块。
- 空闲页总数增加 `n`。
- 空闲链表保持地址升序。
- 与前后物理地址连续的空闲块完成合并。

**Case 1：不存在相邻空闲块**

将回收区域作为独立空闲块插入链表。

**Case 2：与前一个空闲块连续**

将回收区域合并到前一个空闲块，更新其 `property`，移除多余链表节点及头页标志。

**Case 3：与后一个空闲块连续**

将后一个空闲块合并到当前空闲块，更新其 `property`，移除后一个空闲块的节点及头页标志。

**Case 4：与前后两个空闲块均连续**

将三个区域合并为一个连续空闲块，并确保链表中只保留合并后空闲块的头页节点。

## 5. best_fit_nr_free_pages()

**Pre-Condition：**
- 分配器已经初始化。

**Post-Condition：**
- 返回当前空闲物理页总数，不改变管理器状态。

- 复用现有页分配接口、链表工具、页大小及地址转换方式，正确区分页描述符、物理地址和内核虚拟地址。
- 不覆盖 Buddy 使用的 Page 字段、状态位和链表节点。
- 管理信息优先放在申请到的页内，不要求修改 Page。
- 暂不实现 CPU 本地缓存、NUMA、无锁操作等复杂机制。

[Guarantee]
1. 管理器接入
完整实现 slub_pmm_manager 的所有回调：
- init：初始化 Buddy，再初始化 SLUB 的静态 cache 和空链表。
- init_memmap：委托 Buddy 注册可用物理页。
- alloc_pages、free_pages：直接委托 Buddy。
- nr_free_pages：返回 Buddy 的空闲页数。
- check：依次执行 Buddy 和 SLUB 自检。

2. 数据结构与初始化
   - 设置固定大小类别：16、32、64、128、256、512、1024、2048 字节。
   - 每个小对象 slab 占一页，同一 slab 只容纳同一大小类别的槽位。
   - 每个 cache 维护仍有空闲槽位的 slab 链表。
   - 每个 slab 记录所属 cache、底层页、总槽位数、已分配数及 freelist。

   - 计算容量时扣除管理信息、必要的检查信息及对齐开销，不得覆盖管理区或越过页边界。

3. 小对象分配
kmalloc(size) 应：
- 对 size == 0 返回 NULL。
- 选择能够容纳请求的最小大小类别。
- 从对应 cache 的可用 slab 中取得一个空闲槽位。
- 无可用 slab 时，申请一页，初始化管理信息和空闲链表。
- 更新 freelist 和已分配计数；slab 满时从可用链表摘除。
- 分配失败时返回 NULL，不得泄漏页面或破坏已有状态。
4. 小对象释放
kfree(ptr) 应：
- 对 NULL 不做操作。
- 根据原始返回指针找到所属 slab。
- 检查槽位边界及分配状态，使用必要的位图或等效方式检测页内重复释放等错误。
- 将槽位插回空闲链表，减少已分配计数。
- 原先满的 slab 出现空位后重新入链，避免重复挂链。
- 最后一个对象释放后，先摘链并保存底层页信息，再将整页归还 Buddy。
- 页面归还后不得继续访问其中的管理信息。
不合并相邻对象槽位；页面归还后的伙伴合并由 Buddy 完成。
5. 大对象分配与释放
   - 大于 2048 字节的请求直接申请连续页。
   - 按“请求大小 + 管理开销”计算所需页数，兼容 Buddy 向上取整到 2 的幂页数的行为。
   - 记录分配类型、页块首描述符和实际占用页数。
   - 返回满足对齐要求、至少可使用 size 字节的内存。
   - kfree() 应可靠地区分小对象和大对象，并准确归还整个大对象页块。
   - 若通过指针向下按页取整查找管理头，应保证大对象的原始返回指针位于页块第一页。
   - 所有加法、对齐、页数计算和幂次取整均需检查溢出。
6. 自检
slub_check() 至少覆盖：
- 零大小、各大小类别边界及超过最大类别的请求。
- 返回地址对齐，可写满请求范围，多个对象内容不互相覆盖。
- 同一 slab 内的多次分配、释放及槽位复用。
- slab 满、重新出现空位、跨 slab 分配。
- 不同大小类别的独立管理。
- 大对象分配及完整回收。
- 内存不足或超大请求失败时，已有状态不变。
- 全部释放后，Buddy 空闲页数恢复到测试前。
- 每个存活 slab 满足：
已分配槽位数 + 空闲槽位数 = 总槽位数
自检不得遗留对象、页面或链表状态。
